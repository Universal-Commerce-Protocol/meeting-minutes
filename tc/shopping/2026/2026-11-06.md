## 2. Open Discussions & PR Reviews

- **Topic:** Checkout Address Refinements Proposal and Invariant Constraints
  - **Notes:** James Andersen presented pull request 1023, proposing to permit completion-time refinement of redacted buyer and shipping address details to optimize wallet flows such as Google Pay and Apple Pay.
  - **Discussion:** Ilya Grigorik and Drew Olson opposed the proposal, emphasizing that requiring a complete and immutable transaction proposal prior to buyer consent is a critical protocol security invariant preventing malicious post-approval address alterations. James Andersen accepted the decision and agreed to verify whether digital purchase requirements warrant separate iteration.
  - **Decision:** The council rejected modifying checkout addresses post-approval to protect core transaction security invariants.
  - **Context:** [feat(checkout): accept completion-time refinement of buyer and shipping details](https://github.com/Universal-Commerce-Protocol/ucp/pull/1023)
- **Topic:** Recommendations PR Scope and Review Deferral
  - **Notes:** Amit Handa recommended narrowing the recommendations pull request strictly to a search-only design to unblock core use cases before evaluating lookup features.
  - **Discussion:** Ilya Grigorik and James Andersen requested deferring formal review to the Monday deep dive to give implementers and business teams time to evaluate operational feasibility.
  - **Decision:** The council deferred review and decision on scoping the recommendations feature to search-only until the Monday deep dive session.
  - **Context:** [feat(catalog): add purpose and reference_ids to catalog search](https://github.com/Universal-Commerce-Protocol/ucp/pull/902), [feat(catalog): similarity search, recommendations & substitute discovery](https://github.com/Universal-Commerce-Protocol/ucp/pull/974), [feat(catalog): dev.ucp.shopping.catalog.similarity extension](https://github.com/Universal-Commerce-Protocol/ucp/pull/977)
- **Topic:** Purchase Option Extensions and Subscriptions Approval Status
  - **Notes:** Greg Smith and Drew Olson reviewed pull request 890 for purchase options and subscription policies, noting that outstanding review feedback from Payments TC discussions has been resolved.
  - **Discussion:** Ilya Grigorik and Amit Handa noted that one final Governing Council approval is required to merge the pull request.
  - **Context:** [feat: add purchase options extension and subscription policy](https://github.com/Universal-Commerce-Protocol/ucp/pull/890)
- **Topic:** Cart-to-Checkout Conversion Input Simplification
  - **Notes:** Ilya Grigorik introduced pull request 1052 to eliminate ambiguous hybrid checkout creation inputs where both a `cart_id` and raw line items could be supplied simultaneously.
  - **Discussion:** Ilya Grigorik and Gil Greenberg advocated enforcing strict bifurcation: creating checkouts either by reference using a single `cart_id` or by value using a full array of line items.
  - **Decision:** The council agreed to adopt the simplified conversion inputs pending schema updates and re-review.
  - **Context:** [feat!: clarify cart-to-checkout conversion inputs](https://github.com/Universal-Commerce-Protocol/ucp/pull/1052)
- **Topic:** Reference Price Definition and List Price Merge
  - **Notes:** Greg Smith and Ilya Grigorik confirmed that pull request 1031 defining `list_price` as a reference price was merged into pull request 1016.
  - **Discussion:** Amit Handa and Greg Smith agreed to conduct a final review of edge cases and European Union pricing compliance nuances before merging.
  - **Context:** [docs: define list_price once as a reference price](https://github.com/Universal-Commerce-Protocol/ucp/pull/1031), [feat: add optional response-only list_price to item schema](https://github.com/Universal-Commerce-Protocol/ucp/pull/1016)
- **Topic:** Business Profiles Base Shape PR Strategy
  - **Notes:** Greg Smith reviewed the modular business profile pull request series defining a shared `business_summary` model (PR 1017) alongside transactional attribution (PR 1018) and catalog seller references (PR 1019).
  - **Discussion:** In response to feedback on pull request decomposition, Greg Smith agreed to partner with Gil Greenberg to refine the specifications to 95 percent completion prior to council review.
  - **Context:** [feat(common): add business_summary and contact types](https://github.com/Universal-Commerce-Protocol/ucp/pull/1017), [feat(shopping): add seller attribution to cart, checkout, and order](https://github.com/Universal-Commerce-Protocol/ucp/pull/1018), [feat(catalog): add normalized sellers map and seller_id references](https://github.com/Universal-Commerce-Protocol/ucp/pull/1019), [feat: [RFC] Business Identity](https://github.com/Universal-Commerce-Protocol/ucp/pull/939)
- **Topic:** Feed Capability Service and Record Formats
  - **Notes:** Greg Smith and Ilya Grigorik announced that pull request 866 for the bulk catalog feed capability is ready for wider review.
  - **Discussion:** The capability establishes a transport and discovery service agnostic of specific payload schemas, natively supporting UCP shopping records in JSON Lines (JSONL) and Apache Parquet alongside partner-specific custom record formats.
  - **Context:** [feat: feed capability for bulk catalog access](https://github.com/Universal-Commerce-Protocol/ucp/pull/866)
- **Topic:** Fulfillment Events Open Schema and Documentation Standardization
  - **Notes:** Greg Smith presented issue 729 and pull request 979 regarding partner requests to replace open string fulfillment event types with rigid closed enumerations.
  - **Discussion:** Ilya Grigorik argued against closed enums, stating that open extensible schemas are fundamental to UCP evolution, and proposed expanding schema examples and documentation rather than restricting protocol types.
  - **Decision:** The council agreed to maintain the open string pattern for fulfillment events while enhancing documentation and normative examples rather than adopting strict enums.
  - **Context:** [[Proposal]: Standardize consumer-facing fulfillment event types](https://github.com/Universal-Commerce-Protocol/ucp/issues/729), [feat(order)!: standardize fulfillment event types](https://github.com/Universal-Commerce-Protocol/ucp/pull/979)
- **Topic:** Protocol Extensibility and Tooling Layer Warnings
  - **Notes:** Greg Smith and Ilya Grigorik debated methods for encouraging semantic normalization without restricting protocol extensibility.
  - **Discussion:** Ilya Grigorik proposed shifting unknown value feedback to the tooling layer, enabling compilers and validators to issue warnings for unrecognized sentinel values without rejecting valid experimental payloads.
  - **Decision:** The council agreed to implement feedback in UCP schema tooling to emit warnings for unknown values, deferring the specific encoding approach for subsequent discussion.
  - **Context:** [Universal-Commerce-Protocol/ucp](https://github.com/Universal-Commerce-Protocol/ucp)
