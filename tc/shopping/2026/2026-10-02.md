## 2. Open Discussions & PR Reviews

- **Topic:** Subscriptions Modeling and Policy Framework
  - **Notes:** Daniel Wyckoff presented issue 890 regarding modeling recurring subscription contexts in UCP, explaining that the proposal introduces a simple subscription policy and an array of schedules tied to line items.
  - **Discussion:** Amit Handa raised tension regarding how business-defined policies interact with platform choices where buyers select schedules, noting patterns observed across large marketplaces such as Amazon and Walmart. Daniel Wyckoff clarified that this draft represents the first primitive for describing subscription terms, while purchase options form a secondary necessary primitive. Ilya Grigorik argued that purchase options and policies cannot be decoupled because client agents must be able to select subscription choices explicitly. Daniel Wyckoff agreed to publish a second pull request for purchase options so the council can evaluate whether to package both pieces together. Ilya Grigorik confirmed that the subscription policy composes effectively with payment terms (such as an introductory free trial followed by monthly billing), emphasizing its importance for upcoming Black Friday Cyber Monday (BFCM) promotions.
  - **Decision:** The group deferred final commitment on the subscription policy proposal pending review of the secondary purchase options primitive.
  - **Context:** [feat: add subscription policy extension (dev.ucp.shopping.policy.subscription)](https://github.com/Universal-Commerce-Protocol/ucp/pull/890), [[Proposal]: Recurring Billing & Subscription Setup for Checkout](https://github.com/Universal-Commerce-Protocol/ucp/issues/629)
- **Topic:** Identity Provider Account Linking Documentation
  - **Notes:** Amit Handa presented a documentation pull request addressing Identity Provider (IdP) account linking, aiming to allow federated sign-in methods (such as Google or Facebook) to facilitate account linking without creating security vulnerabilities or account takeover risks.
  - **Discussion:** Ilya Grigorik referenced emerging Internet Engineering Task Force (IETF) draft specifications (such as draft-hardt-email-verification) and cautioned that email-based account linking carries significant security nuances. James Andersen supported the proposal and offered to review the security implications, while Amit Handa requested accelerated peer reviews across the council.
  - **Context:** [feat(identity-linking): allow email matching when the IdP is the DNS-delegated authoritative email issuer](https://github.com/Universal-Commerce-Protocol/ucp/pull/876)
- **Topic:** Fulfillment Destinations and Checkout Data Sources
  - **Notes:** Greg Smith introduced a community contribution pull request concerning fulfillment destinations and address books, noting ongoing discussions with the author. James Andersen expanded on the topic, observing that multiple third-party sources—including digital wallets, identity providers, and payment handlers—contribute checkout data (such as fulfillment addresses, billing addresses, and contact info), and argued that UCP currently lacks a unified abstraction to represent these third-party data contributions clearly to users.
  - **Discussion:** Ilya Grigorik cautioned against copying nested data objects directly into checkout by value, advocating instead for a copy-by-reference architecture via an account endpoint where vaulted addresses and instruments are referenced by opaque identifiers. Greg Smith agreed to draft a summary position, and James Andersen noted Meta maintainer Karan Goel shares strong interest. The council agreed that Greg Smith and James Andersen will coordinate a dedicated working session with Karan Goel, Ilya Grigorik, and interested technical council members.
  - **Context:** [docs: clarify saved fulfillment destination selection](https://github.com/Universal-Commerce-Protocol/ucp/pull/735), [docs: clarify business-populated response values for identity-linked sessions](https://github.com/Universal-Commerce-Protocol/ucp/pull/585)
- **Topic:** Ask Capability Review and Fine-Tuning
  - **Notes:** Ilya Grigorik provided an update on the `ask` capability review from Monday's deep dive, reporting consensus to extract a reusable common primitive rather than restricting it to shopping, alongside fine-tuning data boundaries. Amit Handa noted the feedback is straightforward to address and urged fast-tracking the pull request to land the following week.
  - **Decision:** The group agreed to extract a reusable common primitive from the `ask` capability proposal.
  - **Context:** [feat: `ask` capability for natural-language Q&A](https://github.com/Universal-Commerce-Protocol/ucp/pull/538)
- **Topic:** Return Policy Extension Community Feedback
  - **Notes:** Amit Handa presented pull request 634, which underwent extensive revisions based on community feedback and review comments from Greg Smith, establishing return-term fields as minimum guarantees. Amit Handa requested sign-off from Greg Smith and Shopify maintainers to merge the extension next week.
  - **Context:** [feat: add return policy extension (dev.ucp.shopping.policy.return)](https://github.com/Universal-Commerce-Protocol/ucp/pull/634)
- **Topic:** SDK Type Generation and CLI Schema Compilation
  - **Notes:** Greg Smith presented a chain of pull requests adding a `generate-types` subcommand to the UCP CLI, compiling schemas based on selected profiles, capabilities, and extensions into a unified JSON Schema representation to generate data transfer objects (DTOs) across programming languages.
  - **Discussion:** Greg Smith noted that this tooling will deprecate per-SDK pre-processing transformations. Ilya Grigorik highlighted that landing this tooling aligns with the need to enforce schemas in shipped binaries.
  - **Context:** [feat(cli): add generate-types subcommand](https://github.com/Universal-Commerce-Protocol/ucp-schema/pull/84), [feat(codegen): add capability reachability, composition, and generate_types() API](https://github.com/Universal-Commerce-Protocol/ucp-schema/pull/83), [feat(codegen): add directional schema slicing and $ref alignment](https://github.com/Universal-Commerce-Protocol/ucp-schema/pull/82), [feat(codegen): add identifier naming, UCP keyword stripping, and $defs ref rewriting](https://github.com/Universal-Commerce-Protocol/ucp-schema/pull/81)
- **Topic:** Structured Cart Modifications and State-Bound Offers
  - **Notes:** Greg Smith presented a community contribution pull request proposing a structured mechanism for businesses to propose cart modifications and merchant offers bound to specific cart states.
  - **Discussion:** Ilya Grigorik questioned whether cart state binding is necessary and probed whether platforms and agent builders would trust or utilize merchant-recommended products. James Andersen, Greg Smith, Jordan Williams, Julia Downey, and Ilya Grigorik confirmed strong industry demand for personalization, reordering, and upselling (such as phone cases for phone purchases). Greg Smith will carry the topic into Monday's deep dive session to evaluate potential inclusion in the December milestone.
  - **Context:** [feat: add state-bound Offer extension for Cart proposals](https://github.com/Universal-Commerce-Protocol/ucp/pull/773), [[Proposal] Business-driven offer and intervention extension for cart transitions](https://github.com/Universal-Commerce-Protocol/ucp/issues/738)
